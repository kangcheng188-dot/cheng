# 《超级鸡马 · 主机架》制作提示词（自我迭代记录）

> 目标：复刻《超级鸡马》（Ultimate Chicken Horse）的核心玩法，只做一张地图——“主机架”（Mainframe），
> 手机与电脑浏览器都能直接玩。本文件记录我给自己写提示词、自我审查、再改写的全过程：v1 → v2 → v3（实现规格）→ 实测 → v4（最终增补）。

---

## v1（初稿）

> 用 HTML5 Canvas 做一个像《超级鸡马》的平台跳跃游戏。地图叫“主机架”，电脑主板风格。
> 玩家从左边跑到右边的旗子。每回合先从派对盒子里选道具，然后摆放，然后比赛跑到终点。
> 支持键盘和触屏。

### 对 v1 的自我审查

1. **“像”没有落地**：没写清楚原作的回合结构（派对盒 → 放置 → 奔跑 → 计分）、计分规则（终点/首位/陷阱/独行/金币/逆袭，
   “太简单/没有赢家”不得分）、胜利条件，做出来只会是“一个跑酷游戏”。
2. **地图机制缺失**：原作“主机架”的核心机关是背景里两块**不可碰撞的电路板**，被切成 1×1 小格；
   **玩家经过的格子会变色，并在下一回合变成实体方块**，再下一回合又被新路径替换（“每回合都会变化、炸弹炸不掉的地形”）。
   布局是：左边起点，右边终点，中间一个大坑，坑中央有一个小平台。v1 一个字都没提。
3. **一个人没法玩**：原作是多人派对游戏，手机上一个人玩必须有电脑对手，而且电脑要会**真正地跑、跳、爬墙**，
   还要会**摆陷阱**，否则“陷阱分”“独行分”全都没有意义。
4. **手感没定义**：原作手感关键在：可变跳跃高度、冲刺键、贴墙下滑与蹬墙跳、土狼时间、跳跃缓冲。
5. **道具没清单**：没列出道具、没定义旋转、碰撞、伤害归属（谁放的陷阱杀了谁）。
6. **美术方向空泛**：原作是粗描边、圆润卡通、动物双足站立；主机架是深蓝机房 + 绿色电路板 + 服务器机柜。

## v2（第二稿）

> 用原生 JS + Canvas 2D（无依赖、无构建）做《超级鸡马》同人复刻，地图只有“主机架”。
>
> **回合流程**：派对盒（玩家数 +2 个道具，轮流/同时挑）→ 放置（所有人同时放，可旋转，重叠非法显示红色）
> → 奔跑（所有人从起点出发，碰陷阱或掉坑即死）→ 计分板（彩色分段条形动画）→ 下一回合。先到 5 分者胜。
>
> **计分**：终点 1.0；首位 0.2（≥2 人到达时）；陷阱 0.2（别人的陷阱杀死你，分给陷阱主人）；独行 0.6（只有 1 人到达，且总人数 ≥3）；
> 金币 0.2（拿着金币到终点）；逆袭 0.6（落后者到达终点）。所有人都到终点=“太简单了！”、没人到终点=“没有赢家！”，均不计分。
>
> **主机架**：46×26 格。左侧服务器机柜是起点，右侧机柜是终点（红旗），中间大坑，坑中央悬浮 CPU 芯片小平台。
> 两块电路板在坑上方背景中，玩家身体扫过的格子染成该玩家颜色，下一回合变成实体，再下一回合消失、被新的替换；炸弹炸不掉。
>
> **角色**：鸡、马、羊、浣熊，粗描边卡通，跑/跳/滑墙/死亡/庆祝动画。
>
> **道具**：木块（1×1、2×1、3×1、L、2×2）、冰块、蜂蜜、传送带、弹簧、铁丝网、尖刺、电锯、弩、喷火器、黑洞、炸弹、金币。
>
> **操作**：电脑：方向键/WASD + 空格跳 + Shift 冲刺；手机：左侧虚拟摇杆 + 右侧跳/冲刺键。
>
> **电脑玩家**：用 A* 搜索规划路线。

### 对 v2 的自我审查

1. **AI 规划不能是网格 A***：平台跳跃的可达性取决于速度、重力、跳跃时长，网格 A* 会让电脑穿墙或跳不上去。
   必须**在与游戏完全相同的物理步进函数上做搜索**（宏动作：按住某组按键 N 帧），且物理必须**确定性**（固定 60Hz 步长），
   这样规划出的输入序列回放时能分毫不差地复现轨迹；陷阱也要可预测（弩箭、喷火按时间解析计算）。
2. **电脑摆放策略缺失**：没路时要“搭桥”，有路时要“在路线附近放陷阱但不能把路完全堵死”（否则没人得分，自己也得不到分），
   炸弹要炸别人的陷阱。需要用规划器验证可行性。
3. **难度与失误**：完美 AI 很无聊。要有安全边距（陷阱判定放大）、执行噪声、偏离后重规划，才会自然地“失误死亡”。
4. **手机体验细节**：放置阶段手指会挡住道具——道具要显示在手指上方；需要“旋转/放置”按钮；竖屏要提示横屏；
   人类死亡/到达后要能“快进”看电脑跑完；按钮要大；需要暂停。
5. **镜头**：原作奔跑时镜头会跟随所有存活玩家自动缩放；手机屏小，全图太小看不清，必须动态缩放。
6. **性能**：静态背景/地形要预渲染到离屏画布；AI 规划要分帧执行，不能卡住主线程。
7. **音效与音乐**：原作主机架有一首电子风格的歌。需要 WebAudio 合成的电子乐循环（放置阶段加低通滤波，奔跑时全频），
   以及跳跃、落地、死亡、放置、炸弹、弩、喷火、金币、计分等音效。不能用原作音频/素材（版权），全部程序化生成。
8. **细节还原清单缺失**：派对盒开箱动画、玩家光标（玩家色手套+头像）、非法位置红色、炸弹爆炸清除道具、
   死亡爆出羽毛/羊毛、到达终点撒彩带、计分条逐段生长并带类别标签、胜利画面……都要写进规格并逐项检查。

## v3（最终版 · 实现规格）

### 0. 总体约束
- 纯前端：`chicken-horse/index.html` + `js/*.js`（经典脚本，全局命名空间 `UCH`），无构建、无外部依赖（字体除外，且有回退）。
  可直接双击打开，也可部署在 GitHub Pages。
- 所有美术为 Canvas 程序化绘制（原创），所有声音为 WebAudio 合成（原创）。标注“非官方同人作品”。
- 固定 60Hz 物理步长 + 渲染插值无关（渲染用最新状态），保证确定性。
- 手机横屏优先；竖屏显示“请横屏”提示但仍可玩。DPR 最高取 2。

### 1. 单位与地图（主机架 Mainframe）
- 1 格 = 1 世界单位，y 向下。地图 **46 × 26** 格。左右为不可见墙，顶部上方 8 格外为不可见天花板，掉出底部 ⇒ 死亡。
- 地形：
  - 起点机柜：x∈[0,9)，顶面 y=16，一直延伸到底部。出生点 x≈2.2~6.2 一字排开。
  - 终点机柜：x∈[37,46)，顶面 y=16。终点旗杆在 x=42.5，判定区 x∈[41.6,43.4]×y∈[12.5,16]。
  - 中央 CPU 芯片平台：x∈[21,25)×y∈[15,16)，下方 x∈[22,24)×y∈[16,17) 为芯片底座（悬浮于大坑上）。
  - 起点与芯片、芯片与终点之间各 12 格宽的深坑 ⇒ 第一回合必须放道具才能通关。
- **电路板（核心机关）**：两块背景电路板，左 x∈[10,20)×y∈[6,15)，右 x∈[26,36)×y∈[6,15)，各 10×9=90 个 1×1 格。
  - 奔跑阶段，存活玩家碰撞盒（略缩小）覆盖到的电路格被“标记”，染成该玩家颜色并发光（后经过者覆盖颜色）。
  - 回合结束（计分后）：上一批实体格溶解消失；本回合被标记的格子“实体化”成方块（带玩家色的发光数据块），
    在**下一整回合**（派对盒、放置、奔跑）中是实体地形；被道具占据的格子跳过。
  - 实体格与地形一样 **炸弹炸不掉**；道具不能放在实体格上；电路板本身不碰撞，道具可以覆盖在电路板背景上。
- 视觉：深海军蓝机房背景（渐变）、远景服务器机架剪影 + 闪烁 LED（绿/蓝/琥珀）、顶部垂下的线缆束、风扇格栅；
  坑底暗色 + 下落的绿色二进制数据流；地形为钢灰蓝机柜（高光顶边、通风槽、硬盘仓、LED、四角螺丝、深色粗描边）；
  电路板为暗绿 PCB + 金色走线（直角与 45° 折线）+ 焊盘 + 小芯片 + 细网格线 + 沿走线流动的光点；
  终点：旗杆 + 飘动红旗；起点：机柜上的电源图标。

### 2. 角色与手感
- 角色：**小鸡**（白身红冠黄喙细橙腿）、**马**（棕身深色鬃毛长脸）、**绵羊**（白色羊毛团 + 黑脸黑腿）、**浣熊**（灰身黑眼罩环纹尾）。
  双足站立、粗深色描边、大眼睛。动画：待机呼吸、跑步摆腿+身体上下、起跳拉伸、落地压扁、下落、贴墙滑、蹬墙、死亡爆散、终点庆祝。
- 玩家色：P1 红 `#ff5a4f`、P2 蓝 `#3f8cff`、P3 绿 `#3cc95b`、P4 黄 `#ffc234`。
- 碰撞盒 0.7 × 0.92（能钻 1 格高的缝）。
- 物理常量（格/秒）：行走 6.0，冲刺 9.0；地面加速 70、地面减速 60；空中加速 40、空中减速 8；
  重力 46（下落时 ×1.2），最大下落 21；起跳速度 16.2（满按约 3.3 格高）；松开跳跃时若上升则速度 ×0.45（可变跳高）；
  土狼时间 0.1s，跳跃缓冲 0.12s；贴墙（按向墙）下滑最大 3.4；蹬墙跳：水平 8.0 反向、竖直 15.0，之后 0.14s 内水平控制减弱。
- 材质：冰面（加速/减速 ×0.12，冰侧不能贴墙）；蜂蜜（侧面贴住不滑、顶面速度 ×0.4 跳跃 ×0.75、底面倒挂，按跳脱离）；
  传送带（顶面附加 ±4.5 的平台速度）；弹簧（碰到弹面按法线方向弹射 23，侧向弹簧附带 10 的向上分量）。
- 玩家之间不碰撞。

|---|---|---|---|
| 木块 1×1 / 2×1 / 3×1 / L / 2×2 | 各异 | 是 | 实体木头 |
| 冰块 2×1 | 2 | 是 | 实体，滑 |
| 蜂蜜 1×1 | 1 | 否 | 实体，粘 |
| 传送带 3×1 | 3 | 是（换方向） | 实体，顶面带人 |
| 弹簧 1×1 | 1 | 是（4 向） | 实体，弹面弹射 |
| 铁丝网 1×1 | 1 | 否 | 非实体，触碰即死 |
| 尖刺 1×1 | 1 | 是（4 向） | 实体，碰到尖刺面即死 |
| 电锯 2×2 | 4 | 否 | 非实体，圆形半径 0.92 即死，旋转 |
| 弩 1×1 | 1 | 是（4 向） | 实体；每 2.2s 射箭（首发 1.0s），箭速 13，飞到实体停止，碰到即死 |
| 喷火器 1×1 | 1 | 是（4 向） | 实体；周期 3.4s：关 1.6 → 预警 0.4 → 喷 1.4，火焰长 3 格（遇实体截断） |
| 黑洞 1×1 | 1 | 否 | 非实体；半径 4.5 内吸引（越近越强），中心 0.45 内即死 |
| 炸弹 1×1 | — | 否 | 放下立即爆炸，半径 2.6 内清除所有已放道具（不影响地形/电路实体格/起终点） |
| 金币 1×1 | 1 | 否 | 拿到后头顶跟随；死亡则金币回原位；到终点得“金币”分并永久移除 |
- 放置规则：只能放在地图内；不能与地形、实体电路格、其它道具、出生区（x∈[1,8)×y∈[13,16)）、终点区（x∈[40,45)×y∈[12,16)）重叠。
- 派对盒：每回合 `玩家数+2` 个道具（最多 6），权重随机（方块类多、陷阱中、炸弹/金币少）；第一回合至少 2 个方块类。
- 伤害归属：每个陷阱记录主人；被他人陷阱杀死 ⇒ 陷阱主人 +陷阱分；自杀/掉坑不给分。

### 4. 回合流程（状态机）
`标题 → 选角 → [派对盒 → 放置 → 奔跑 → 计分 →（电路格切换）]* → 胜利`
- **派对盒**：箱子落下→盖子弹开→道具弹出排在面板上；玩家光标（玩家色手套 + 角色头像）选取，选中的道具飞向玩家；
  电脑 0.8~2.5s 内随机/按策略选。全员选完 0.6s 后进入放置。
- **放置**：全员同时。道具跟随光标（触屏时显示在手指上方 1.6 格），合法=正常+柔光，非法=红色+✕。
  旋转键；放下时“砰”一声 + 尘土。已放置的玩家头像打勾。30s 超时：合法则自动放下，否则丢弃。炸弹放下即爆。
- **奔跑**：出生“噗”地出现 → “准备…开始！”（0.9s，电脑趁机规划）。镜头跟随存活玩家自动缩放（最小视野 22 格宽），
  上限 60s。人类都已结束后显示“快进”按钮（×3）。全部结束 → 0.8s → 计分。
- **计分板**：每名玩家一行（头像+名字+横条），按类别逐段生长并飘出标签：终点(玩家色) / 首位(金) / 陷阱(红) / 独行(紫) /
  金币(黄) / 逆袭(青)。终点线 5 分处有旗子标记。“太简单了！”/“没有赢家！”大字提示。点击/按键继续（6s 自动继续）。
- **计分规则**：到达人数 0 ⇒ 没有赢家，不计分；到达人数 = 全部 ⇒ 太简单了，只计金币分；其余情况：
  终点 1.0；首位 0.2（到达 ≥2 人）；独行 0.6（只有 1 人到达且总人数 ≥3）；陷阱 0.2/次；金币 0.2；
  逆袭 0.6（到达终点时处于最后一名且与第一名差距 ≥1.5 分）。先 ≥5 分者胜（同时过线取高者，完全相同则继续）。
- **胜利画面**：胜者角色大跳庆祝 + 彩带 + 最终分数条；“再来一局 / 回到标题”。

### 5. 电脑玩家
- **规划器**：在同一个 `Physics.step` 上做加权 A*。宏动作 = 保持输入 6 帧；动作集 {无, 右, 左, 右+跳, 左+跳, 跳} × {冲刺, 行走}。
  启发式 = 从终点出发的网格 Dijkstra 距离场 / 冲刺速度。状态去重键：x/0.25, y/0.25, vx 桶, vy 桶, 着地/贴墙/按跳。
  陷阱判定在规划时按难度放大（困难 0.06 / 普通 0.14 / 简单 0.22）。分帧执行（每帧 ≤6ms），预算 30000 次扩展。
- **执行**：逐帧回放输入；每帧比对预测状态，偏离则停下并从当前状态重规划。
  难度噪声：简单/普通在随机时刻扰动一个宏动作（松跳/晚跳），困难几乎不扰动；起跑有 0.1~0.6s 反应延迟。
  找不到路：先原地等待，3s 后“放弃”（跳进坑里，原作常见场面）。
- **选道具**：无路 ⇒ 方块类优先；有路 ⇒ 陷阱优先；关卡拥挤 ⇒ 炸弹；带随机性。
- **放道具**：先用规划器求参考路线（无路则求“最远可达点”）。
  - 无路 + 方块：在最远可达点前方可跳距离（3~6 格、上下 ±2）生成候选，用规划器评估“最近可达距离”的改进，选最好者。
  - 有路 + 陷阱：在路线附近 1~2 格生成候选，验证“放下后自己仍可通关”，按路线耗时增加量打分，难度越高候选越多。
  - 炸弹：瞄准他人陷阱最多的位置；金币：放在路线旁略绕的位置。
  - 光标平滑移动到目标后放下（看起来像人在操作）。

### 6. 操作
- **电脑**：←→/AD 移动，空格/W/↑/Z 跳，Shift/X 冲刺；放置阶段：方向键/WASD 移动光标或鼠标，空格/回车/左键放下，
  R/Q/E/右键/滚轮旋转；Esc/P 暂停。第二名本地玩家：方向键 + 回车/小键盘0 跳 + 右 Shift 冲刺（启用双人时 P1 只用 WASD）。
  支持手柄（A 跳/确认，X 冲刺，B/LB/RB 旋转，Start 暂停）。
- **手机**：奔跑时左半屏动态摇杆（推到 75% 以上自动冲刺），右下大“跳”键 + “冲”键；派对盒点选；
  放置时拖动（道具显示在手指上方）+ “旋转”“放置”按钮；右上暂停键；奔跑结束后“快进”键。

### 7. 界面与表现
- 字体：标题用站酷快乐体（ZCOOL KuaiLe）+ Fredoka，失败回退系统黑体；粗描边白字、轻微倾斜、弹性缩放动画。
- 音乐：128 BPM 电子乐（底鼓、踩镲、贝斯琶音、方波主旋律、机器人“嘟嘟”元音合成），菜单/放置阶段低通。

## 实现后的自我审查（实测发现的问题 → 写回提示词）

用无头浏览器（桌面 1280×720 键盘/鼠标、手机 844×390 多点触控）和 4 电脑观战模式实测后，发现 v3 还有这些漏洞：

| # | 实测现象 | 根因 | 修正（写入 v4） |
|---|---|---|---|
| 1 | 电脑在“准备”阶段一直规划不完，站着不动 | 主线程分时给 4 个电脑的时间太少，超时又重来，死循环 | 规划放到 **Web Worker 线程池**；超时不再重来，结果迟到时按“静止+无定时陷阱→整体顺延，否则重算”处理；无 Worker 时退回主线程分时 |
| 2 | 喷火器场景永远找不到路 | 距离场用 Float32 存储，和 Float64 比较时丢节点；另外“原地等待”状态被去重剪掉 | 距离场改 Float64；有定时陷阱时，静止状态按 0.3s 时间段区分 |
| 3 | 电路格下的矮缝跳不过去 | 宏动作最短按跳 6 帧，跳不出低跳 | 动作集加入“轻点跳”（只按前 2 帧） |
| 4 | “没路”时规划耗尽预算很慢 | 在坑边反复探索 | 连续 6000 次扩展无进展即停止 |
| 5 | 所有电脑同时放道具，全堆在同一处 | 共用同一份“最远可达点” | 电脑按顺序错开思考，后思考的基于最新地图（含前面放下的道具）重新分析 |
| 6 | “太简单了”回合太多 | 电脑执行太完美 | 提高失误率（简单 1/45、普通 1/100、困难 1/400 每宏动作），上回合太简单时更偏好陷阱 |
| 7 | 偶尔有电脑卡住直到 60 秒 | 局部路径走完后原地不动 | 看门狗：4 秒无进展或卡住 1.5 秒 → 放弃（冲向坑），3 秒后仍存活判出局 |
| 8 | 快速点按空格没反应 | 按下与松开在同一帧 | 键盘“锁存”：两帧之间按下过就算一次 |
| 9 | Esc 暂停后再按 Esc 又立刻暂停 | 键盘事件和帧轮询各处理一次 | 键盘暂停只在按键事件里处理，手柄 Start 只在轮询里处理 |
| 10 | 终点红旗（红底黄星）像某国国旗 | 美术 | 改为红白三角锦旗 |
| 11 | 1P 玩家色是红色，和“不能放”的红色混淆 | 配色 | 非法位置 = 暗色蒙层 + 红色虚线 + ✕，合法 = 玩家色实线 |
| 12 | 手机放置阶段按钮压住底部玩家栏；按下的按钮变黑 | 布局 / 颜色函数不支持 rgba | 按钮上移到右侧；按下态改为叠加半透明白 |
| 13 | 计分板在桌面太大、和横幅重叠 | 缩放系数没封顶 | 计分板缩放上限 1.3，横幅跟随面板顶部定位，条尾显示当前总分 |
| 14 | 缺少原作的“地图标题卡”和放置网格 | 细节遗漏 | 开局显示“主机架 MAINFRAME”标题卡；放置阶段显示格线与禁放区斜纹 |

## v4（最终版增补）

在 v3 基础上追加/修改：

- **AI 线程**：`js/ai_worker.js` + `js/aipool.js`。请求类型：`plan`（奔跑路线）、`analyze`（地图分析，供选道具）、`place`（放道具决策）。
  世界以 `{uid, version, items, circuit}` 序列化，线程内按 key 缓存重建。单文件版用内联源码生成 Blob Worker。
- **规划器**：14 个宏动作（含轻点跳）；Float64 距离场；定时陷阱下允许原地等待；无进展早停。
- **电脑行为**：错峰放置；失误率按难度；看门狗放弃机制。
- **交互**：键盘锁存；暂停单一入口；手机放置按钮位于右侧上方；非法放置有独立视觉语言。
- **表现**：地图标题卡、放置网格、禁放区斜纹、三角锦旗、计分板显示总分。
- **与 v3 数值的差异（以实测为准）**：起跳速度 17.2（满跳 3.36 格、冲刺跳 6.5 格、走跳 4.3 格）；
  触屏放置改为“相对拖动”（手指在屏幕任意处拖，道具不被遮挡）；奔跑镜头最小视野手机 22 格、桌面 30 格；
  派对盒最多 7 个道具且同种最多 2 个。
- **验收**：
  - 4 电脑观战跑完整局（16 回合，5 分获胜），无报错，平均 60fps；
  - 手机触屏：点选道具、相对拖动放置、摇杆 + 跳跃按钮全部可用；
  - 键盘：菜单方向键导航、选道具、移动/旋转/放置、跑跳冲刺、Esc 暂停/继续；
  - 物理单测：滑墙、蹬墙跳、弹簧（5.6 格）、冰面、传送带、蜂蜜倒挂、尖刺/喷火/弩箭判定。
